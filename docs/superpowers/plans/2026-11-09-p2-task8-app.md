# Phase 2 Task 8 (App: Lịch sử Run, Màn hình Duyệt, Khung Panel & UC-09 UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nâng cấp ứng dụng web (FastAPI + React) để lưu lịch sử run vào Postgres (`runs`), chuẩn hoá route `POST /runs/{uc}` (`uc01`, `uc09`), hỗ trợ chạy/resume/duyệt bài trên workflow LangGraph của UC-09 qua SSE và hiển thị màn hình lịch 8 bài cùng cổng phê duyệt của con người (khoá nút duyệt khi bài còn claim số liệu chưa `supported`).

**Architecture:** Backend (`app/backend/main.py`) ghi nhận và cập nhật trạng thái mọi run vào bảng `runs` trong Postgres (kèm fallback đọc từ thư mục `traces/` khi chạy test offline không có DB), cung cấp `GET /runs`, hàm `run_output(run_id)`, `POST /runs/uc01`, `POST /runs/uc09`, `POST /runs/{run_id}/approval` (trả `202` hoặc `409` khi không chờ duyệt / còn `blocking_claims`), và `POST /runs/{run_id}/resume` (`202`). Workflow `agent/graph.py` đính kèm `calendar`, `article`, `claim_report`, `blocking_claims` vào các sự kiện trace (`calendar_planned`, `await_approval`) để stream SSE `GET /runs/{run_id}/events` giữ nguyên hợp đồng Phase 1 mà frontend vẫn hiển thị được trực tiếp bảng lịch 8 bài và màn hình duyệt. Frontend (`app/frontend/src/`) bổ sung tab `UC-09`, tab `Lịch sử run`, và component `CalendarView.tsx` tái sử dụng `ArticleView` + `FactCheckPanel`.

**Tech Stack:** Python 3.12, FastAPI, psycopg 3, LangGraph, React 19, TypeScript, Vite, pytest.

**Spec:** [docs/roadmap/phase-2.md](../../roadmap/phase-2.md) mục "Task 8: App" (issue #18) và mục "Task 7: UC-09" (dòng DoD màn hình lịch trên app).

- Không sửa logic hay file thuộc sở hữu của UC-01, UC-02, UC-03, UC-04 (`.github/CODEOWNERS`, D-16); giữ nguyên các route `POST /runs/uc02`, `POST /runs/uc03`, `POST /runs/uc04` và các component `ResearchReportView`, `ArticleView`, `FactCheckPanel`.

### Task B: Backend — `POST /runs/uc09`, `POST /runs/{run_id}/approval` và `POST /runs/{run_id}/resume`

**Files:**
- Modify: `agent/graph.py`
- Modify: `app/backend/main.py`
- Modify: `tests/test_app.py`

**Interfaces:**
- Consumes: `build_graph`, `start_graph`, `resume_graph`, `approve_graph`, `make_checkpointer`, `graph_config`, `ScriptedWorkflowLLM` (`agent/graph.py`); `ApprovalDecision`, `ApprovalConflictError`, `ApprovalBlockedError` (`agent/uc09.py`); `ClaimReport`, `blocking_claims` (`agent/claims.py`).
- Produces:
  - `POST /runs/uc09` body `{"brief": str, "topics": list[str], "auto_approve": bool = False}` → `200 {"run_id": str}`.
  - `POST /runs/{run_id}/approval` body `ApprovalDecision` → `202 {"run_id": str, "status": "accepted"}`. Run không ở trạng thái chờ duyệt → `409`. `decision == "approve"` khi `blocking_claims` khác rỗng → `409` kèm danh sách claim chặn (`detail={"message": ..., "blocking_claims": [...], "claims": [...]}`).
  - `POST /runs/{run_id}/resume` → `202 {"run_id": str, "status": "accepted"}` (404 nếu không tìm thấy checkpoint).
  - Event `decision` `action="await_approval"` trong trace có kèm `calendar`, `article`, `claim_report`, `blocking_claims`.
