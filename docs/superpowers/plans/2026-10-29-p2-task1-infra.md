# Phase 2 Task 1 (Hạ tầng) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dựng Postgres + pgvector và service mini-web bằng Docker Compose, thêm `agent/db.py` (`connect`, `migrate`) cùng `agent/schema.sql`, fixture `db` cho pytest, và cho CI chạy test DB trên service Postgres.

**Architecture:** `docker-compose.yml` có 2 service: `db` (pgvector) và `miniweb` (chạy server của Task 3 trên thư mục `evals/` mount chỉ đọc). `agent/db.py` mở connection từ `DATABASE_URL` và chạy `schema.sql` trong một schema cho trước; mỗi test DB chạy trong schema `test_<hex>` riêng rồi xoá. CI thêm service container `pgvector/pgvector:pg17` vào job `lint-test`.

**Tech Stack:** Docker Compose v2, `pgvector/pgvector:pg17`, `psycopg[binary]>=3.2`, python-dotenv (đã có), pytest, GitHub Actions service containers.

**Spec:** [docs/roadmap/phase-2.md](../../roadmap/phase-2.md) mục "Task 1: Hạ tầng" (issue #11), cùng mục "Ràng buộc chung" của file đó.

## Lệch so với khối Interface trong roadmap

Các điểm dưới đây đặc tả chưa nói, nhưng task sau dựa vào. Task C ghi lại vào khối Interface của Task 1 trong `phase-2.md`.

1. `connect(env: Mapping[str, str] | None = None)`: `env=None` thì `load_dotenv()` rồi đọc `os.environ`, giống `GeminiLLM`. Test truyền `env` để không đọc phải `.env` của máy dev.
2. Connection trả về có `autocommit=True`. `PostgresSaver.setup()` của Task 7 cần autocommit, và Task 8 ghi bảng `runs` không mất dữ liệu vì quên `commit()`.
3. Lỗi kết nối: thông báo của đặc tả, rồi lý do của psycopg trong ngoặc (dòng đầu, ví dụ `password authentication failed`). Không có lý do thì người có Postgres cài sẵn chiếm cổng 5432 sẽ bị bảo "chạy docker compose up -d" dù compose đang chạy.
4. Extension `vector` luôn tạo trong `public`. `migrate` đặt `search_path` của connection thành `<schema>, public`. Mọi lệnh trong `schema.sql` phải chạy lại được (`IF NOT EXISTS`) và không ghi tên schema.
5. Fixture `db` trả connection đã `migrate` xong; test của Task 4 có sẵn bảng.
6. Cổng của cả hai service chỉ bind `127.0.0.1`, không mở Postgres ra mạng LAN. `miniweb` chỉ mount `./evals`, không mount cả repo, để `.env` không lọt vào container. Vì vậy server của Task 3 không được import gì ngoài `evals/` và 3 gói đã cài.

## Review Focus

1. **Xoá schema test kéo theo extension.** `DROP SCHEMA test_x CASCADE` xoá luôn `vector` nếu extension được tạo trong schema đó, làm hỏng test sau và dữ liệu ở `public`. Mong đợi: extension luôn ở `public`. Kiểm ở `test_vector_extension_lives_in_public` (Task B).
2. **Compose chưa chạy, hoặc máy Windows đã có Postgres chiếm cổng 5432.** `connect` phải báo lỗi rõ, nêu lý do, không lộ mật khẩu và không treo. Kiểm ở `test_connect_unreachable_says_run_compose` (Task B).
3. **Ghi dữ liệu rồi mất vì chưa commit.** Task 8 ghi `runs` và Task 7 tạo bảng checkpoint đều cần connection autocommit. Kiểm ở `test_connect_autocommits` (Task B).
4. **Thành viên không cài Docker.** Phần lớn nhóm chỉ làm UC của mình: `pytest` vẫn phải xanh, test DB skip kèm lý do. Riêng trên CI thì phải fail chứ không skip. Kiểm ở Task B Step 7.
5. **`.env` chưa có `POSTGRES_PASSWORD`.** `docker compose up -d` phải dừng ngay và nêu tên biến. Nếu không, container Postgres sẽ tự thoát mà `-d` không báo gì. Kiểm ở Task A Step 6.

```python
import pytest

from agent.db import connect, migrate
from agent.llm import ConfigError

UNREACHABLE = "Không kết nối được Postgres ở DATABASE_URL, chạy docker compose up -d"


def test_connect_without_url_names_variable():
    with pytest.raises(ConfigError, match="DATABASE_URL"):
        connect({})


def test_connect_unreachable_says_run_compose():
    with pytest.raises(ConfigError) as e:
        connect({"DATABASE_URL": "postgresql://postgres:s3cret@127.0.0.1:1/postgres"})
    assert str(e.value).startswith(UNREACHABLE)
    assert "s3cret" not in str(e.value)


def test_migrate_is_idempotent(db):
    schema = db.execute("select current_schema()").fetchone()[0]
    assert schema.startswith("test_")
    migrate(db, schema)
    migrate(db, schema)
    assert db.execute("select to_regclass(%s)", (f"{schema}.runs",)).fetchone()[0] is not None


def test_vector_extension_lives_in_public(db):
    row = db.execute(
        "select extnamespace::regnamespace::text from pg_extension where extname = 'vector'"
    ).fetchone()
    assert row == ("public",)
    db.execute("select '[1,2,3]'::vector")  # kiểu vector dùng được từ schema test


def test_connect_autocommits(db):
    assert db.autocommit
```

`to_regclass` nhận tên đã ghi schema, nên test không bị bảng `runs` ở `public` (nếu máy dev từng migrate `public`) đánh lừa.

- [ ] **Step 5: Viết `agent/db.py`**

Docstring module một đoạn ngắn như `agent/llm.py`. Hằng `UNREACHABLE` giữ đúng câu của đặc tả (giống hằng trong test). Hai hàm:

- `connect(env: Mapping[str, str] | None = None) -> psycopg.Connection`: `env is None` thì `load_dotenv()` rồi `env = os.environ`. Lấy URL bằng `require_env(env, "DATABASE_URL")`. Gọi `psycopg.connect(url, autocommit=True, connect_timeout=5)`. Bắt `psycopg.OperationalError as e` rồi `raise ConfigError(f"{UNREACHABLE} ({lý do})") from e`, với lý do là dòng đầu của `str(e).strip()`. libpq không đưa mật khẩu vào thông báo lỗi, nhưng không được ghép URL vào thông báo.
- `migrate(conn: psycopg.Connection, schema: str = "public") -> None`: ba lệnh `conn.execute`, theo thứ tự: `CREATE SCHEMA IF NOT EXISTS {}`, `SET search_path TO {}, public` (tên schema đưa vào bằng `psycopg.sql.Identifier`), rồi nội dung `SCHEMA_SQL = Path(__file__).with_name("schema.sql")` đọc bằng `encoding="utf-8"`. psycopg 3 chạy được nhiều lệnh trong một `execute` khi không truyền tham số.

- [ ] **Step 6: Thêm fixture `db` vào `tests/conftest.py`**

Thứ tự tìm URL và cách xử lý khi thiếu là quyết định của đặc tả nên chép nguyên. Thêm import `os`, `secrets`, `Path`, `dotenv_values`, `psycopg.sql`, `connect`, `migrate` lên đầu file:

```python
ROOT = Path(__file__).resolve().parent.parent


@pytest.fixture
def db():
    """Connection tới schema test_<hex> mới, đã migrate; schema bị xoá sau test."""
    url = os.environ.get("DATABASE_URL") or dotenv_values(ROOT / ".env").get("DATABASE_URL")
    if not url:
        if os.environ.get("CI"):
            pytest.fail("CI phải có DATABASE_URL để chạy test DB")
        pytest.skip("Chưa có DATABASE_URL: chạy docker compose up -d rồi điền .env")
    conn = connect({"DATABASE_URL": url})
    schema = f"test_{secrets.token_hex(4)}"
    migrate(conn, schema)
    yield conn
    conn.execute(sql.SQL("DROP SCHEMA {} CASCADE").format(sql.Identifier(schema)))
    conn.close()
```

`dotenv_values` chỉ đọc file, không ghi vào `os.environ`, nên fixture không làm đổi môi trường của các test khác.
